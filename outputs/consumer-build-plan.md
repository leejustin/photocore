# Consumer build plan: "Finish the trip"

Branch: `feat/consumer-trip-book`. One chunk per hour (chunks 5 to 7 built back to back on request, order 7, 5, 6). Each chunk ends with
`swift build`, `swift run photo-engine-checks`, `swift test`, the iOS simulator
test (`xcodebuild test -scheme EngineTests`), and a commit.

Product summary: free culling on the phone, paid hosted finish that turns the
keepers into an online photobook with an AI diary, guest contributions, and an
Instagram pack. See the product doc for the full story.

## Running the iOS engine test

`.swiftpm/` is gitignored, so the `EngineTests` scheme lives in
`Scripts/ios-engine-test.sh`, which writes it before running `xcodebuild test`.

## Running the iOS app

`Scripts/ios-app.sh` builds `Apps/PhotocoreiOS`, installs it on the booted
simulator, grants Photos access and launches it. Seed photos first with
`xcrun simctl addmedia booted /path/*.JPG`. Launch options
`-PhotocoreAutoOpen YES` opens the newest trip and `-PhotocoreAutoSwipe YES`
opens the swipe review when the cull finishes. Screenshots go in the gitignored
`outputs/screenshots/ios/` because they show real library photos.

## Log

- Chunk 1: added `.iOS(.v18)`; replaced AppKit image fallback in StyleMatcher with Image I/O; guarded the loopback `LocalCurationServer` to macOS; added `PhotoEngineAppleTests` (Swift Testing) that runs the full pipeline on synthetic JPEGs.
- Chunk 2: `PhotoLibraryIngest` exports a trip from Photos to 1024 px JPEGs with date and GPS, skips screenshots, and keeps a `library-index.json` so resumed trips skip current files; `PhotoLibraryWriter` saves keepers as an album and Favorites. `UtilityShotDetector` drops receipts and menus (six or more text lines covering 6% of the frame; one large false box on shapes is ignored). `AutoEnhance` is the free-tier edit. The runner now checkpoints the analysis cache every `checkpointInterval` photos, so a cancelled or killed cull resumes. Found and fixed a Vision deadlock when two culls ran at once: all Vision analysis now shares a process-wide gate. 8 Swift tests pass on Mac and iPhone simulator.
- Chunk 3: iPhone app in `Apps/PhotocoreiOS` (hand-written Xcode project, local package reference). Home finds trips from capture dates (`TripDetector`: 20-hour gap, 20 photos minimum, runs over 21 days split at the largest pause), the trip screen reads, culls and shows keepers, the swipe sheet resolves close calls (`KeeperSelection`), and keepers save as a Photos album. Verified in the iPhone 18 Pro simulator with 140 Pycon photos: trips detected, cull ran, swipe worked, album saved. Fixed: simulator aesthetics returns a constant score, so it is skipped there and the cache is keyed by platform. Found and logged: Vision face signals vary between runs on the same photo (see evaluation log); follow-up is a single shared face detection pass. 18 tests pass on Mac and simulator.
- Chunk 4: photo metadata now carries GPS (optional, old manifests still decode). `SceneLabeler` (Vision classification, keepers only), `SaliencyCropper` (4:5, 9:16, 1:1 crops centered on attention saliency), `PlaceNamer` (1 km grid cells, one reverse-geocode per cell, disk cache). `SubjectAwareEdit` lifts the subject and quiets the background through a feathered foreground or person mask; `FinishRenderer` is the paid render (auto adjust, subject edit, optional crop). `TripFactsBuilder` writes `trip-facts.json` with time, place, labels, faces and crops per keeper for chunk 5. Fixed a test deadlock from stacked culls (see evaluation log): Vision suites are serialized and every Vision caller goes through the gate. 25 tests pass on Mac (5 runs) and iPhone simulator.
- Chunk 7: `StreamedCuller` analyzes Photos thumbnails in memory in batches and keeps only `signals.plist` (about 5 KB a photo; the 28-photo trip went from 6.9 MB of working copies to 132 KB), resumes without rereading, and shares `PhotoPipelineRunner.decide` with the Mac runner (eval output unchanged: 6 kept of 28). `CullGuard` refuses under 200 MB free, pauses when the phone runs hot, and shrinks batches in Low Power Mode. Trips split above 1,500 photos. `TripQueue` runs one trip at a time. Set aside hides non-keepers into the "Photocore · Set aside" album with one-tap restore; favorites, edited, shared and album photos are never touched; delete is capped at 500 and goes through the iOS confirmation into Recently Deleted; every step is logged. Verified in the simulator: set aside 25 (my confirmation, then iOS's own hide prompt), restore 25. Fixed: a confirmation dialog that dropped its plan on dismiss; the protection check moved off the main thread. Delete was not exercised in the simulator; the cap and log are unit tested. 32 tests pass on Mac and simulator.
- Chunk 5: `BookSectioner` makes chapters by local day, place and three-hour pauses (12 photos max). `TripBookComposer` sends Claude only the facts and 512 px thumbnails keyed "p1", "p2" (no file names), asks for schema-checked JSON (`claude-opus-5-5`, effort medium, `fallbacks: "default"`), and falls back to the offline `TemplateDiaryWriter` on refusal or outage. Owner edits live in `edits.json` and survive regeneration; only title, intro, headings, diary and captions are editable. `BookRenderer` writes one self-contained page (clean book theme, optional scrapbook theme, lightbox, owner edit mode, guest hearts and notes when an endpoint is set). `InstagramPack` renders a 1080 x 1350 carousel that walks every chapter and 1080 x 1920 stories, plus `caption.txt`. New `photo-engine book <folder>` command. Local time now follows a GPS place's time zone, then the camera's recorded offset: the Pycon Sony files say 06:16 -07:00 because the camera clock stayed on Pacific time. Claude was not called live (no credentials here); the request shape and parsing are tested against a mocked endpoint. 40 tests pass on Mac and simulator.
- Chunk 6: `TripStore` and `Routes+Trips` add the paid finish: create a trip (owner token shown once, stored hashed), upload keepers, queue a finish job on the existing serial job queue, and a cheap `/v2/preview` for the upsell. `TripFinisher` keeps every owner keeper, culls guest photos at 30% and drops guest frames within 0.35 visual distance of an owner photo, then builds facts, diary, photos, page and Instagram pack; refinishing keeps owner edits. Public `/b/{slug}/` serves only html, jpg and txt from the book folder (no traversal, CSP, nosniff); edits need the owner token (the server token is refused); guest notes, hearts and uploads have size and count limits. The iPhone finish card shows a before and after from the server, uploads only keepers with progress, and ends with Share, Open and Edit. Verified end to end in the simulator against a local server: 6 keepers uploaded, book served and readable at phone width. Fixed: Hummingbird route conflicts for the book paths. README rewritten around the consumer product. 40 Swift tests, 48 checks and 10 server checks pass; payments are not built (the card says "Test build: no charge").
- Chunk 8: Claude removed. `DiaryWriters.make` picks `PHOTOCORE_WRITER` if set, then Gemini (`gemini-3.1-flash-lite`) or DeepSeek (`deepseek-flash`) when their key is set, both through the OpenAI-compatible chat API with images, then Apple's model (Private Cloud Compute with photos on OS 27, otherwise on-device, written one chapter at a time with `@Generable` output), then the offline writer. On this Mac (macOS 26.6) the on-device model ran for free but wrote plain, label-like captions, which is why a configured hosted key wins. No hosted run yet: no Gemini or DeepSeek key here; request shape, parsing and fallback are tested against a mocked endpoint. Fixed: the CLI blocked its main thread while the geocoder and MapKit waited for it.
- Chunk 9: `GroundFact` list with sources (location, nearby landmarks from MapKit within 150 m, sun times computed locally, sign text read from photos, scene labels, people counts, owner note, calendar events). `GroundingCheck` uses Apple's NaturalLanguage tagger: names, numbers, nouns and event verbs must trace to a fact; label lists are rejected too; failing fields fall back to fact-only text and are counted in `book.json`. On a location-stamped test copy of the Pycon photos the book named Belém Tower, Lisbon's time zone and the owner's "PyCon" note; the first ungrounded on-device run had invented a long flight, stars and a balcony, which the checker now removes. Trip dates now use the trip's time zone. 45 tests pass on Mac and simulator.
- Chunk 10: full-bleed cover with the title set over it, intro in serif, chapter strip, numbered chapters with place and date, the diary as a pull quote, and a layout rhythm per chapter (an edge-to-edge opener, then portrait pairs and alternating landscape singles and pairs). Light and dark, phone and desktop checked in the browser; print styles start each chapter on a new page. Writing fixes found while looking: chapter headings must differ from the title and each other; captions use only confident labels with readable names; no filler captions; the on-device model writes title, intro, headings and diary only, because its captions were poor.
- Chunk 11: walked the app from a fresh install. Found and fixed: the Photos permission prompt appeared before the app said anything (new welcome screen first); home copy said "nothing is uploaded" while the paid tier uploads (now says nothing leaves unless you finish a trip); two orange primary buttons competed (album saving is now secondary); finished books were forgotten on relaunch (now remembered per trip, with a "Book ready" badge, read in-app); no way to tell the diary what the trip was (optional note plus calendar suggestions, asked only on tap; a short note becomes the title). Trip cards use the place name when the cover has GPS.
- Safety bug found in the walkthrough: set aside used to hide photos, but iOS locks hidden photos away from apps, so Photocore could hide them and never unhide them. The "restore" logged success while 25 photos stayed hidden (seen in the simulator's Photos database). Set aside is now album-only, never hides, writes a pending log entry before any change, and restore treats the album as the source of truth. The 25 test photos hidden earlier must be unhidden by hand in the simulator's Photos app (it asks for the device passcode).
